# Zobdino Brand & Discovery Guide

## Canonical identity

- Product: **Zobdino**
- Persian name: **زبدینو**
- Preferred combined form: **Zobdino · زبدینو**
- Official domain: `https://zobdino.ir/`
- Target GitHub organization: `https://github.com/Zobdino`
- Target canonical product repository: `https://github.com/Zobdino/Zobdino`

## Positioning

Zobdino is an open-source Persian book-summary and audio-learning platform with an AI-assisted research, scripting, text-to-speech, audio-QA and publishing pipeline.

## Natural discovery language

Use these concepts naturally in product copy; do not keyword-stuff:

- Persian book summaries
- Farsi book summaries
- Persian audio summaries
- Farsi audio learning
- AI book summaries
- Persian text-to-speech
- Persian TTS
- nonfiction book summaries
- audio learning
- open-source content pipeline
- AI content automation
- RTL Next.js
- GitHub Actions publishing

## Messaging pillars

1. **Persian-first** — language, RTL UX and listening quality.
2. **Audio-first** — short, practical listening experiences.
3. **Automation-first** — reproducible content and audio pipeline.
4. **Verifiable** — hashes, QA, evidence and immutable release assets.
5. **Copyright-aware** — no full-book redistribution or chapter-by-chapter translation.
6. **Open Source** — visible engineering lifecycle on GitHub.

## Legacy naming

`KetabCast / کتاب‌کست` is a historical project identity.

Do not use the legacy name on new active product surfaces unless explaining migration history or preserving historical provenance.

Historical release assets, evidence and published transcripts may retain the old repository identity intentionally.

## README guidance

The repository README is a product landing page first and a developer entry point second.

It should answer:

- What is Zobdino?
- Why is it useful?
- What is unique about the engineering approach?
- How is content produced and verified?
- What is live today?
- How can someone contribute?
- Where is the canonical website?

## Search quality

Prefer useful, specific prose over repeated keywords.

Every title and summary should help humans first. Search visibility should come from semantic clarity, consistent naming, strong repository metadata, accurate topics and authoritative links.

# v0.2.0-beta.5.1.16 — TTS Long-Form Segmentation + Audio Coverage Gate

## Trigger

The first controlled production run from v0.2.0-beta.5.1.15 proved that official Gemini Interactions SSE streaming works, but also proved that a successful long-form stream can cover only a small fraction of a ~1100-word canonical chunk.

- Production run: 32116283883
- Exact source: v0.2.0-beta.5.1.15 / 9c74f9378b7249bf7cc5d39c4332841ae70e33c0
- Resume source: run 32106512757 / artifact 9314798536
- Failed checkpoint artifact: 9316995825
- Failed checkpoint digest: sha256:a490d9a1ddca38730a3b6ae2f2c0a0d1002096a348376e0bb5fc4af540397ebf
- Schedar canonical chunk 1: 1090 words, streamed 616320 bytes at 24 kHz mono PCM, resulting checkpoint duration 12.84 seconds
- Schedar canonical chunk 2: 1101 words, streamed 3634560 bytes at 24 kHz mono PCM, resulting checkpoint duration 75.72 seconds
- Final male dry narration: 90.7 seconds
- Failure: atomic-habits/male outside the existing 10–22 minute duration gate
- No terminal content_blocked occurred in this run.

The failed artifact contains both valid Sulafat canonical checkpoints and two provenance-correct but obviously truncated Schedar canonical checkpoints. v0.2.0-beta.5.1.15 resume-seed checked hash/provenance and positive duration, but had no duration-per-word floor, so those male WAVs would otherwise be reusable.

## Root cause / design gap

- Streaming transport was fixed in v0.2.0-beta.5.1.15.
- The remaining issue is long-form request sizing and coverage validation.
- Canonical chunks remain about 500–1400 words; Atomic Habits uses 1090 and 1101 words.
- Google recommends splitting longer TTS transcripts into smaller chunks when generating long-form audio.
- A successful SSE stream must not be assumed to cover the full requested transcript solely because audio bytes were returned.
- A canonical checkpoint must never be written or reused until its duration is plausible for its word count.

## Released contract

- The two canonical chunks remain unchanged, preserving existing transcript hashes and valid Sulafat checkpoint reuse.
- Fresh TTS inside a canonical chunk is split deterministically at paragraph boundaries, capped at 220 words per segment.
- Oversized paragraphs are split only at sentence boundaries; if a safe sentence-boundary split cannot be proven, generation fails closed.
- Segment concatenation preserves the exact spoken word sequence.
- Every generated/restored segment must satisfy a conservative audio coverage floor of 0.25 seconds per word.
- Every canonical chunk must satisfy the same floor before its checkpoint can be written or reused.
- The r13 male 12.84s/1090-word and 75.72s/1101-word checkpoints are rejected as truncated and are not copied into resume metadata.
- Valid canonical Sulafat checkpoints remain reusable.
- Verified canonical checkpoint reuse seeds recovery eligibility for every deterministic segment hash of that same text.
- Segment WAV checkpoints and accepted Interaction IDs are independently durable so rate-window or provider interruption can resume without repeating completed segments.
- Segment pending Interactions retain the existing bounded two-window same-ID policy.
- Existing terminal content_blocked durable fail-closed semantics remain unchanged.
- Runtime TTS network requests remain globally bounded at 24 and paced at no faster than one request every 12 seconds.
- Explicit free-tier request-window or daily quota outcomes still fail closed and checkpoint progress.
- No transcript wording is changed.
- No production dispatch or media/player promotion is performed by this release lifecycle.

## Provider contract

Google documents Gemini 3.1 Flash TTS streaming through the Interactions API and recommends splitting long-form transcripts into smaller chunks because longer outputs can lose consistency. The exact 220-word bound is a conservative application-level control, not a provider-published hard limit.

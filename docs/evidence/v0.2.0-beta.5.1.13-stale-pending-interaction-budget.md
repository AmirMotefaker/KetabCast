## Contract

- Preserve verified completed WAV checkpoints unchanged.
- A newly accepted pending Interaction starts with one consumed polling window.
- A verified pending Interaction may receive at most one additional polling window.
- Maximum pending Interaction polling windows per ID: 2.
- After that budget is exhausted, the stale ID is retired before any further GET polling.
- The renderer may then make one normal fresh generation attempt for the same chunk under the existing global network cap and quota/safety rules.
- Any newly accepted replacement Interaction is checkpointed before polling.
- Existing content-safety, free-tier 429, transient retry and hard request-cap behavior is unchanged.

## Backward-compatible migration

Schema-v1 sidecars from v0.2.0-beta.5.1.12 did not contain an explicit poll-window counter.

- Legacy pending sidecar without reusedFrom => infer 1 consumed window.
- Legacy pending sidecar with reusedFrom => infer 2 consumed windows.

This makes failed artifact 9170553292 deterministically stale without relying on wall-clock age.

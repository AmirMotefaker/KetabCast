# v0.2.0-beta.5.1 — Dual-Voice Production Foundation

## Goal

Prepare production-safe full-episode rendering for the two voices already
selected by human listening:

- Sulafat / Warm
- Schedar / Even

The current Piper production audio remains untouched and continues to be the
fallback until all required Gemini variants are generated, ASR-QA verified,
uploaded as immutable assets, and promoted through a later player/metadata PR.

## Why batches

The observed Free Tier contract in the selected-voice renderer is 10 Gemini
TTS network requests per day/project/model. A full book/voice uses two balanced
chunks.

Five books × two voices × two chunks = 20 successful requests, so the new
workflow uses three free-tier-safe batches:

- batch-a: Atomic Habits + Deep Work = 8 successful requests
- batch-b: Think Again + Zero to One = 8 successful requests
- batch-c: Leading Teams = 4 successful requests

The hard network cap remains 10 per run.

## Source truth

Unlike the historical alpha voice-review workflow, the new renderer reads the
current production transcripts directly from `src/content/episodes.json`.
Before TTS, legacy spoken product branding is normalized from KetabCast /
کتاب‌کست to Zobdino / زبدینو for the new narration artifacts.

## Integrity

- production `src/content/episodes.json`: unchanged in beta.5.1
- existing five Piper MP3 references: unchanged
- selected voice provenance: pinned
- Gemini response format: pinned to `{ type: "audio" }`
- every dry narration: faster-whisper round-trip QA
- every podcast asset: FFprobe duration gate
- every uploaded media asset: GitHub digest + bytes + public download-back SHA
- no asset is exposed by the consumer player in this foundation release

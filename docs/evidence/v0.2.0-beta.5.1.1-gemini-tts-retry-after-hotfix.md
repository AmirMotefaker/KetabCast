# v0.2.0-beta.5.1.1 — Gemini TTS Retry-After Hotfix + Live Status

## Context

Dual-Voice Batch A run `31516399979` failed before ASR QA/media upload while
starting Atomic Habits / Sulafat.

The provider returned HTTP 429 with:

- metric: `generate_content_free_tier_requests`
- limit: `10`
- explicit short retry hint: `Please retry in 23.145143415s`

The beta.5.1 renderer incorrectly treated the generic metric + `limit: 10` as
proof of daily exhaustion.

## Hotfix

The renderer now:

- classifies daily exhaustion only from explicit per-day quota identifiers or
  explicit daily/per-day language
- parses `google.rpc.RetryInfo.retryDelay`
- parses `Please retry in <seconds>s`
- waits for the provider retry window plus a small safety margin
- applies a 7-second minimum request-start interval
- keeps the hard network cap at 10
- self-tests transient-vs-daily quota classification in validate mode

## Product safety

This hotfix does not change:

- `src/content/episodes.json`
- any existing Piper production asset
- dual-voice media assets
- the player audio source

Batch A Issue #53 remains the production tracking issue.

## Live project status

The homepage now includes a static development-status panel backed by
`src/lib/project-status.ts`.

It displays:

- current release version
- 5/5 production-audio readiness
- Dual Voice verified-variant progress
- current milestone and GitHub Issue
- GitHub Release history

Every subsequent dual-voice milestone will update this status so progress is
visible on GitHub Pages after the normal `main` deployment.

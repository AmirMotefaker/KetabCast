# v0.2.0-beta.5.1.7 — Gemini TTS Completed-Interaction Audio Materialization

## Trigger

Controlled Batch A run `31572749438` from exact tag
`v0.2.0-beta.5.1.5` (`686f5ff95065d570a5ad8eb845de20c47ef9bf04`)
failed on the first `atomic-habits/female/Sulafat` chunk.

The generation POST was accepted and returned an Interaction ID with
`status=completed`, but that initial snapshot had no steps/content/audio data/audio URI.
The renderer immediately raised `TTS_INTERACTION_COMPLETED_WITHOUT_AUDIO`.

No QA, evidence artifact, immutable media publication, or player mutation occurred.

## Root cause

`resolveAcceptedInteraction()` treated `completed` without immediately visible audio as
an unrecoverable terminal condition. Therefore it never issued a GET for the already
accepted Interaction ID to observe a later materialized audio payload.

## Fix

- Preserve the accepted Interaction ID.
- `queued` / `in_progress` continue using same-ID GET polling.
- `completed` without audio now receives at most 6 same-ID materialization GET polls.
- These GETs increment `interactionPollRequests` only.
- Generation POST hard cap remains exactly 10.
- No duplicate generation POST is allowed after an Interaction ID is accepted.
- `response_format` remains `{ type: "audio" }` with no `delivery` property.
- Existing terminal status and 15-minute global poll timeout behavior remain.
- After the bounded grace is exhausted, the renderer still fails closed with
  `TTS_INTERACTION_COMPLETED_WITHOUT_AUDIO`.

## Deterministic validation

The static Interaction state-machine self-test covers:

`completed/no-audio -> same Interaction ID poll eligible -> completed/with-audio`

A second async runtime self-test now executes the real
`resolveAcceptedInteraction()` loop with injected deterministic dependencies:

1. success path: initial `completed/no-audio` -> same Interaction ID GET #1
   still has no audio -> same Interaction ID GET #2 exposes inline audio -> PASS;
2. fail-closed path: persistent `completed/no-audio` performs exactly 6 same-ID
   GETs and then raises `TTS_INTERACTION_COMPLETED_WITHOUT_AUDIO` before any
   seventh GET.

The runtime test also verifies poll numbering, API-key forwarding, the 5-second
poll interval contract without actually sleeping, audio materialization through
the production parser, and that the same Interaction ID is retained throughout.

The completed-without-audio counter is cumulative for the lifetime of the accepted
Interaction and is not reset if a provider snapshot temporarily reports a pending
status between completed snapshots.

## Safety

This hotfix does not dispatch Gemini TTS and does not modify:

- `.github/workflows/dual-voice-production.yml`
- `src/content/episodes.json`
- production Piper audio
- player behavior
- published production episode metadata

`media-dual-v0.2.0-beta.6` must remain absent until the separately controlled Batch A rerun.

## Official API basis

Google's May 2026 Interactions schema documents `GET /interactions/{id}` as the
retrieval endpoint for the full Interaction step timeline. Gemini TTS documentation
uses `response_format: { type: "audio" }` with `Api-Revision: 2026-05-20`.

The need for a bounded post-completion materialization grace is based on the observed
provider behavior in run `31572749438`; the official documentation does not promise
a specific materialization delay.

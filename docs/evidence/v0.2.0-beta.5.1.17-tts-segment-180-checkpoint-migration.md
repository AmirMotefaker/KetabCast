# v0.2.0-beta.5.1.17 — 180-Word TTS Segments + Prefix Checkpoint Migration

## Trigger

The first controlled production run from v0.2.0-beta.5.1.16 proved that the long-form segmentation and coverage gate work as intended, but a 211-word Schedar segment can still return truncated audio.

- Resume source: run 32116283883 / artifact 9316995825

- Schedar segment 001: 99 words / 31.320s / valid checkpoint preserved
- Schedar segment 002: 140 words / 42.480s / valid checkpoint preserved

- No terminal content_blocked or quota classification caused this failure.

## Root cause / design gap

- v0.2.0-beta.5.1.16 correctly rejected truncated segment audio, but the 220-word application bound was still too large for this Schedar response.
- Lowering the deterministic bound changes the total segment count even when a valid prefix segment keeps identical text, index, path, word count, and hash.
- Treating segmentCount as exact provenance would therefore discard valid prefix checkpoints for metadata-only plan-count drift.

## Released contract

- MAX_TTS_SEGMENT_WORDS is reduced from 220 to 180 in renderer and resume-seed.
- Atomic chunk 1 changes from [99,140,211,138,181,145,176] to [99,140,110,101,138,85,96,145,176].
- Historical segment 001 (99 words) and 002 (140 words) keep identical text, index, path, words, and spokenSegmentSha256, so they remain reusable.
- segmentCount remains written as metadata for new checkpoints, but historical stored counts are accepted when they are sane positive bounded counts greater than segmentIndex.
- Exact identity still requires book/role/provider voice/canonical chunk index/segment index/path/word count/script hash/chunk hash/segment hash, plus WAV hash/duration/coverage where applicable.
- Pending Interaction sidecars use the same safe segmentCount migration rule while preserving exact Interaction ID, provenance, and poll-window checks.
- Every generated/restored segment still requires at least 0.25 seconds of audio per word.
- Existing SSE streaming, 24-request hard cap, 12-second pacing, two-window same-ID pending policy, durable segment checkpoints, and terminal content_blocked fail-closed semantics remain unchanged.
- No transcript wording is changed.
- No production dispatch or media/player promotion is performed by this release lifecycle.

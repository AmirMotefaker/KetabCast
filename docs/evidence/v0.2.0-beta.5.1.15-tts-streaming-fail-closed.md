## Root cause / design gap

The existing contentBlockedRecoveryState counters were process-local only. Starting another production run would recreate the counters at zero, which would bypass the intended cross-run meaning of the fail-closed classifier budget.

The non-streaming fresh-generation path also repeatedly demonstrated a provider state where an accepted Interaction reached completed status without materialized audio.

## Released contract

- Fresh Gemini 3.1 Flash TTS generation uses the official Interactions streaming mode:
  - stream=true
  - Accept: text/event-stream
  - audio is accumulated only from step.delta events whose delta.type is audio
- interaction.created IDs are checkpointed before the streamed response is consumed further.
- A streamed error with code content_blocked fails closed.
- Existing pending Interaction resume remains supported for provenance-verified historical checkpoints.
- Existing stale pending Interaction policy remains unchanged: 2/2 retires before any old-ID GET.
- Existing free-tier, transient retry, recovery, and hard-network caps remain bounded.
- Terminal content_blocked outcomes write a .content-blocked.json sidecar.
- dual-voice-resume-seed carries terminal content-blocked state into resume-index.json.
- A matching prior terminal content-blocked state refuses another generation POST and requires a new code release.
- Inherited terminal content-blocked state is re-checkpointed with current-run provenance before refusing a new POST, so the fail-closed chain remains durable across repeated failed resumes.
- Successful output removes stale pending/content-blocked sidecars after the WAV checkpoint is written.
- No transcript text is modified by this release.
- No production dispatch or media/player promotion is performed by this release.

## Provider contract

Google documents Gemini 3.1 Flash TTS streaming through the Interactions API with stream=true and audio delivered by step.delta audio events. The Interactions streaming transport is SSE.
